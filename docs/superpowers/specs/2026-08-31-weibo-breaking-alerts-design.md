# 微博突发爆点提醒设计

## 目标

每 30 分钟抓取一次微博热搜榜，将可能的突发爆点聚合成事件；仅在事件首次达到可解释的爆点阈值时，经 `QQBotService.Notify` 推送给已开启现有微博热搜订阅的群和私聊。

## 范围与非目标

- 范围：微博热搜快照、事件评分、去重、状态管理、QQ 纯文本通知、投递失败处理。
- 不新增 QQ 订阅模型；由 qq-bot 的 `Notify` 决定当前订阅接收者。
- 不进行事件事实核验、新闻正文抓取或 LLM 语义判断。
- 不发送同一事件的后续排名更新。

## 依赖与接口

抓取来源沿用 `spider-server` 的 `WeiboHot`，使用 `title`、`url`、`rank`、`hot` 和 `tags`。

通知使用 qq-bot 新增的向后兼容 gRPC 接口：

```proto
rpc Notify(NotifyReq) returns (Resp) {}

message NotifyReq {
  string content = 1;
}
```

调用方不使用 `SendMsg`，不传 QQ 号或群号。`Notify` 仅投递给已有微博热搜订阅者。

## 快照与事件身份

每个采样周期保存完整榜单快照。条目以标准化标题（去首尾空白、统一全半角、压缩内部空格）作为第一版事件键。

事件记录至少包含：事件键、标题、链接、首次/最后出现时间、上次排名、上次热度、上次标签、状态、已推送时间、最后触发原因、重试次数和当日通知计数。

第一版不合并不同标题的同一新闻；宁可漏合并，也不把不同事件错误去重。

## 候选与评分

条目必须先满足至少一个强信号，才计算并进入候选：

1. 新上榜且进入 Top 10；
2. 相比上一周期排名上升至少 15 位，且当前进入 Top 20；
3. 热度较上一周期至少翻倍，且当前进入 Top 20；
4. 当前位于 Top 20，且标签包含 `爆`、`沸`、`当前爆词` 之一。

评分规则：

| 信号 | 分值 |
| --- | ---: |
| 新上榜 | 2 |
| 当前 Top 3 / Top 10 / Top 20 | 3 / 2 / 1 |
| 排名上升 15–29 位 / 30 位以上 | 2 / 3 |
| 热度增长 100%–199% / 200% 以上 | 2 / 3 |
| `爆`、`沸` 或 `当前爆词` 标签 | 3 |
| `新` 或 `荐` 标签 | 1 |

总分达到 5 分且至少满足一个强信号即为爆点：新上榜进入 Top 10；排名提升至少 15 位且进入 Top 20；热度至少翻倍且进入 Top 20；或位于 Top 20 且含 `爆`、`沸` 或 `当前爆词` 标签。`新/荐` 只能加分，不能单独触发通知。

## 状态机与去重

```text
observed -> candidate -> notified -> completed
                   |          |
                   +----------+  （未达分或已推送：不重复通知）
```

- `observed`：首次在快照中出现，尚未达到阈值。
- `candidate`：本周期达到阈值；调用 `Notify`。
- `notified`：通知已被 qq-bot 接受，同一事件不再通知。
- `completed`：连续两次不在榜，或连续两次排名下滑后进入完成态；完成态不推送。

`completed` 事件至少沉寂 12 小时后，若重新满足“新上榜且 Top 10”条件，创建新的事件轮次；否则保持完成态。

## 推送与失败处理

- 不设置每日或单周期推送上限；每个独立且满足条件的事件都会调用 `Notify`，同一事件仍按状态机去重。
- `Notify` 返回成功且消息为 `没有可推送的订阅者`：标记该事件已处理，不补发。
- `Notify` 返回 RPC 错误：下一个采样周期最多重试一次；再次失败则标记为投递失败并不再重试。
- 任何一轮通知成功后，不因排名、热度或标签继续变化而补推。

## 消息格式

使用纯文本，链接保留为完整 URL：

```text
💥💥💥 微博突发爆点
【孙宇晨说长文写了十几个小时】
排名：新上榜 → 第1
标签：当前爆词
触发：新上榜 + Top 10 + 爆点标签
链接：https://weibo.com/xxxx
```

没有标签时省略“标签”行；没有上一周期排名时用“新上榜”，否则展示“第N → 第M”。触发原因按实际命中的规则组合，保持可解释。

## 可验证性

- 单元测试覆盖评分阈值、Top 20 限制、标题去重、事件完成、12 小时再爆发、无每日上限、重试上限和消息渲染。
- 集成测试使用伪造快照序列与伪造 `Notify` 客户端，断言通知次数和正文。
- 运行日志记录事件键、评分、触发原因、状态转换与通知结果；不记录 QQ 接收者或 Cookie。
